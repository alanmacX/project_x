# 冰箱贴模板规范 · 1.0

适用于 App 内置单卡模板、组合模板和离线预览。新增模板必须按本规范交付代码、极端数据检查和实拍/渲染对照。当前实现：39 款单卡、5 组一体式组合；组合的 13 个内部数据槽位不出现在单卡列表。

## 1. 产品模型

- **单卡模板**：一个普通 card、一种 capability；`template` 决定呈现方式，原来的 capability 持有动态数据。用户仍能移动、缩放、旋转、编辑数据、换色和替换照片。
- **铺满画布**：单卡打开原来的 `template.fill`；背景、画框仍由 canvas 渲染，禁止模板自己画第二套画框。
- **组合模板**：一次插入一组普通 card；共用 `groupId`。每张仍只有一种 capability、独立来源和数据配置。组合外观按一张完整表盘设计：一个主底面、一个主读数、透明辅助信息槽位。
- **创作**：继续使用原来的卡片与能力配置。模板不改写创作卡片，也不引入新的文档/绑定/同步系统。

## 2. 组合的视觉要求

参考 Apple Watch Modular / Modular Duo / Ultra Modular 的**信息层级和槽位组织**，以及 StandBy 的远距离阅读。每组必须有自己的整体构图和视觉性格。

| 部分 | 必须满足 |
| --- | --- |
| 主信息 | 唯一视觉中心；以时间、课程、日期或人物为主角。先决定用户第一眼看到什么。 |
| 辅助信息 | 1–2 个有用途的角色，例如下一个日程、电量、出发天数；沿同一基线、横条或盘面组织。 |
| 表面 | 仅一个 primary 槽位绘制底面。其他槽位 `surface=false`，无圆角盒、投影、卡框或独立背景。 |
| 配色 | 同组默认使用同一组 background / ink / accent 语义色；强调色用于选中日、进度、时针等少量信息。 |
| 字体 | 同组共享字族、数字语言和正文层级。数字字体使用已授权的 TemplateDigits；中文使用系统字体。 |
| 构图 | 组合不使用分割线，以留白、对齐和字体层级组织信息。主读数与辅助文字不得相撞；背景可重叠，信息区域必须留足空间。 |
| 个性化 | 内容取自用户数据；照片支持选择和已有离线抠图。组合配色整组切换，控件明确标注组合配色；撤销/重做恢复整组原配色。位置仍可自由调整。 |
| 小尺寸 | 必须检查 180vp；主读数清楚，辅助文字不能承担唯一关键信息。不靠堆小字增加信息量。 |

禁止用已有独立模板缩成几张小方块来充当新组合。禁止为了像表盘而加装饰性假数据、固定时间或假电量。禁止复制 Apple 字体、表盘图像、商标和精确外形。

## 3. 目录与几何契约

- 单卡公开目录：`CardTemplate.CARD_TEMPLATES`。ID 一经发布不可复用为其他设计。
- 组合目录：`CompositionCatalog.COMPOSITIONS`；定义 ID、revision、名称、每个槽位的稳定 ID / capability kind / 语义 role / 矩形 / primary。
- 每组恰好一个 primary；所有辅助槽位在主底面以内；同级辅助区域互不覆盖。
- 方形使用 300×300 设计坐标，横向使用独立编排的 300×150；`compositionLayout()` 显式声明横向槽位。禁止把方形非等比拉长。
- 纵向画布放置居中的方形组合，保留用户追加创作空间。工厂适配 344 宽的原画布坐标，y 按原来的 470 归一化。
- 槽位的局部 scene 宽 300，高为 `300 * card.h / card.w`。文字、图片、路径都遵守相同局部坐标。
- 薄辅助槽位必须保留高度；存储 normalization 和编辑最小尺寸检查已识别组合槽位，禁止恢复为普通卡片的 32vp 最小高度。
- 新增组合必须同时登记目录、横向布局和场景实现。工厂对缺少整体设计的 ensemble 返回空数组，没有小卡平铺兜底。

## 4. 信息与极端状态

1. 纯函数 `cardTemplateScene(card, tick)` 只读数据，不改 card，不读文件、不发网络、不启动定时器。
2. 使用原来的日期、日程、课表、时区计算函数；禁止另写一套数据逻辑。时间由宿主传入。
3. 文本必须提供明确的 `w/h/lines`，由 `TemplateTextLayout` 做测量、缩字、换行、截断；禁止以字符数量估算固定字号。
4. 数字优先保持完整并缩字；长标题可两行，地点等次要信息可省略。禁止截出半个 emoji、组合重音或旗帜。
5. 未配置日期显示 `—`；空课表和空日程保留简短状态；未知电量显示 `—`，0 必须显示 0。
6. 倒计时区分过去/未来；闰年、跨年、DST、六行月份、100% 和非有限数值必须过检查。
7. 改背景/强调色时检查文字对比，浅强调色上用深色字，不能固定白字。
8. 相片组合默认等比完整显示图片和主体（contain），禁止用铺满裁切（cover）截掉头部或四肢；预览必须使用真实图片尺寸。图片缺失仍有完整布局；宽/高照片与抠图 zoom/offset 极值不影响读数。切换主体效果必须立即生效。

## 5. 渲染、缓存与性能

| 使用处 | 实现契约 |
| --- | --- |
| 编辑 / 桌面卡片 | `TemplateFace` + `TemplatePaint` 消费共享 scene。 |
| 首页离屏预览 / 导出 | `TemplateSnapshot` 消费相同 scene；使用 `offscreen` 明确选择。不要依赖离屏 Canvas.onReady。 |
| 设计网页 | `previewer/renderer.js` 适配共享 scene，不手写第二套模板排版。 |
| 智能多色 | `CardColorDistribution` 消费相同 scene，透明辅助槽位不能被当成实色底面。 |
| 缓存 | `previewer/build.cjs` 生成渲染指纹；场景、字体或视图变更后必须重建。修改卡片内容/几何必须让现有预览键失效。 |

图层统一：0 装饰/文字、1 图片、2 图片上方文字、3 前景主体；按模板需要使用。不为每个模板创建 WebView、计时器、图片副本或独立截图缓存。复用 capability 数据与已有照片资产；不把动态内容烘焙成生产位图。

## 6. 兼容性与素材

- 继续使用 state schema 2；原来的 card、capability、groupId、canvasId 与系统 Form binding 保持原身份。
- `template` 可选；无此字段的旧卡片保持原样。新增设计不对旧文档自动重排、替换或删除。
- 模板作品包使用原来的 v3；旧 v1/v2 按原规则读取。所有资产经过已有导出嵌入/导入 ID 重映射路径。
- 新 revision 不能改变旧槽位的语义；需要改为另一种 capability 时新增稳定 ID。已存坐标由文档保存，目录只控制新插入。
- 默认优先代码绘制与用户照片；素材需免费可商用许可、原始来源与授权记录。禁止 AI 位图装饰默认进入生产资源。字体许可证一并保留。

## 7. 新增模板的最短流程

1. 填写 [AUTHORING.md](AUTHORING.md) 的设计记录，明确主信息、辅助角色和定制项。
2. 单卡加公开定义与共享场景；组合加 `CompositionCatalog` 的方/横向布局、`CompositionScene` 的槽位场景及公开 ensemble 定义。参考 `mix-modular`。
3. 新照片模板接已有选择/抠图控件；新定制项必须可撤销、可保存、可导出，不能只改网页。
4. `node previewer/build.cjs` 更新生产模型和渲染指纹。
5. `npm run templates:check`。该命令运行单卡、组合、极端文本、视图缓存检查和生成物校验。
6. 用实际共享渲染代码检查：方形、横向、180vp；空数据、超长中文/英文/emoji、实际照片、四套配色。查看 [组合验收页](../../design/template-standard-2026-11-01/index.html)。
7. 原生编译，模拟器验收添加 → 编辑数据 → 返回首页预览 → 保存/重开。更改渲染管线时额外检查桌面预览。提交验证记录和可复现截图。

发布门槛：所有自动检查通过、实际画面无溢出/遮挡、主次清楚、默认配色统一、旧作品可打开。不能只附设计图而遗漏原生实现。
