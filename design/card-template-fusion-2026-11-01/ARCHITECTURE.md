# 卡片模板与冰箱画布的融合方案

2026-11-01 · 设计提案与交互原型。本文没有修改正式 App 的存储、迁移或 Form。

## 1. 产品模型：同一张卡，既能直接用，也能继续贴

保留现有关系：**一个桌面实例绑定一个 canvas，canvas 包含多个 card，card 最多一个 capability。** 新增专属外观渲染器，不新增“成品 widget”实体、模板专用画布或嵌套 canvas。

用户看到的模板是一件好看的成品；系统保存的是正常 card。它单独铺满 canvas 时，就是一个完整小组件。缩小、移动后，它和便签、课程表、照片卡一起组成冰箱。两种用法可以在同一个 canvas 内继续编辑，桌面绑定保持原 canvasId。

| 层次 | 承担什么 | 不承担什么 |
| --- | --- | --- |
| capability | 当前 card 的数据语义、配置、系统数据结果 | 模板位置、色彩、图片构图 |
| card | 数据 + 自由外观或专属模板 + 本卡个性内容；移动/旋转/排序的对象 | 另一棵嵌套 widgets 树 |
| canvas | 卡片组合、背景、尺寸、场景与桌面绑定 | 要求每张卡都长得一样 |
| 模板目录 | 创建 card 的设计定义和默认参数 | 用户作品的唯一存储地址 |
| 组合配方 | 一次创建多个普通 cards 的布局 | 自动跟随商店更新的在线实例 |

一个时钟可以显示时间、年月日、星期，这些由同一时间上下文推导。下节课来自 timetable，旅行还有几天来自 countdown；要一起呈现时创建独立卡片。多张卡可以用原有 groupId 作为一组移动，仍逐卡选择数据。

### 两个入口，同一条落地路径

- **首页新建 → 模板**：选设计 → 选目标尺寸 → 换自己的照片/内容 → 创建 canvas + card。默认构图已完成，可立即添加到桌面；不要求先认识 card/canvas 术语。
- **画布内添加 → 模板 / 自己创作**：选模板往当前画布加 card；自己创作进入原编辑器。保留当前画布中的其他卡、背景和绑定。
- **编辑已有卡片**：数据在“内容”，设计在“外观”。兼容的模板可切换，照片/抠图和原 capability 保留；改变数据类型走原来的能力选择，并单独保留兼容设计草稿。
- **继续组合**：用户主动选择“继续组合”时，先在编辑预览中展示安排，确认后把单卡铺满改为小卡位置；支持一次撤销。后台不因添加/删除一张卡就自动填满或重排。
- **组合配方**：第二阶段提供；配方只在创建时落地为普通 cards。向已有作品应用时默认添加，不替换整幅。不要在首期新造一个模板商店导航。

现有首页继续展示用户 canvas。模板发现放在新建入口；不把首页改成商品墙。新用户可以挑一张喜欢的卡直接完成，熟练用户保留原来贴冰箱的流程。

## 2. 外观封装与自由创作的接缝

模板有固定构图、个性槽位与少量有界参数；不要求用户进图层树手调设计师的每个字。以照片时钟为例：

- 固定：数字构成、光影配方、各尺寸的可读布局、背景/时间/主体的合成顺序。
- 可定制：个人照片、抠图、裁切、主体位置/大小、可选配色与字形、景深开关、12/24 小时制、时区。
- 额外自由元素：延用 card.elements，加入手写字、贴纸或局部装饰。先保持普通叠加，不让用户元素直接引用模板内部节点 ID。需要精确前后关系时提供“时间后 / 主体前”两个语义位置，默认原有前景层。
- card 的 x/y/w/h/rot/z、groupId、隐藏状态继续由 canvas 管。模板只处理自己的局部坐标。
- 预设变化只改当前 card；不存在改一张主题、所有用户作品随之变化的隐式规则。
- 退出专属模板回“自己创作”时，保留 capability、个人照片及用户元素，恢复原来的基础外观。模板个性参数保留为草稿；不把一次返回基础编辑设计成不可逆的拆散或位图化。

### 三种呈现形式

1. **照片卡**：矩形/圆角矩形，完整画面；适合单卡铺满，也能作一枚矩形冰箱贴。
2. **贴纸**：模板作者设计好的主体+数字轮廓；保留薄边与轻落影，具有冰箱贴质感。首期先交付照片卡与无底，完整异形轮廓在 Form 命中/裁切/阴影验收后加入。
3. **无底**：背景透明，时间和主体直接落在 canvas 上；局部阅读衬底按需使用。可点击范围由实际可见内容与合理触控扩张决定，透明角不出现矩形按压底色。

呈现形式属于设计的支持列表。例如翻页钟保留机身，纸本日期保留纸面，不强制给它们“无底”；照片时钟支持多种形式。任意比例不拉伸字形：作者提供 square / wide / portrait 局部布局与最低可读尺寸，缩小时减少次要内容。2×2、2×4、4×4 指 canvas 宿主尺寸，card 布局根据实际分配到的局部宽高选择，不能拿宿主尺寸替代 card 尺寸。

## 3. 景深：现有能力能接上

代码已有 `CanvasElement.depthEnabled/depthForeground/depthCrop/depthSourceAspect`、`subjectDepth`、`depthCapabilityFront`；`DepthComposition.ets` 同时支持卡内与 group 景深。这次首先实现卡内模板，跨卡遮挡保留为显式组合动作。

合成：**原图或纯色背景 → 时间 → 清晰抠图主体 → 日期/用户前景元素**。

- 原图与抠图前景使用同一个 Cover/crop 变换。移动照片时两层一起移动，避免出现双轮廓；主体独立移动只用于纯色抠图模式。
- 景深默认只遮住数字少量边缘。根据 alpha 掩码和数字包围区选择初始构图；实际遮挡覆盖关键笔画或时间区太多时，优先移动时间、减小主体，再回退为时间在前。用 00:00、11:11、23:59 和实际字形进行测试，不能只看 09:41。
- 背景虚化选项仅在有完整原图时出现；透明主体+纯色背景不放无效的虚化滑条。原图的柔化背景离线生成一次，主体保持清晰。不在滑动、退出或每分钟刷新时重复抠图/模糊。
- 不将“原图模糊 + 前景”包装成真实深度图：第一阶段采用静态层次，App 和桌面显示相同构图；不做依赖传感器持续更新的视差，也不为了露出被主体挡住的背景添加生成式补图。
- 无底样式重视文字对背景的对比，延用本机照片取色与阅读衬底。默认小阴影，避免所有字都套重描边。
- 主体/背景处理失败时沿用上一份有效资源；首次失败显示完整原图+前置时间，个人照片不消失。

贴纸的分钟变化由原生文字重绘，不把整张卡烘焙成每分钟一张图。主体 alpha/轮廓只提取一次；数字描边随字体绘制，触控使用稳定的文字区域与主体轮廓，不每分钟跑一次全卡轮廓提取。

## 4. 小范围代码改造

### 推荐的可选扩展（示意，未入正式模型）

```ts
// 保持 FridgeState.schemaVersion = 2。
// card.capability、capBox、elements、照片字段及几何字段保持原用途。
interface CardDesign {
  version: 1;
  id: 'photo-clock';
  revision: 1;                 // 固定渲染版本，升级不偷偷改老作品
  presentation: 'photo' | 'bare' | 'sticker';
  params: { palette: string; depth: boolean; typeface: string };
  // 图片与裁切沿用 elements/已有 depth 字段，避免两份资源所有权。
}
// FridgeCard.design?: CardDesign
```

模板 manifest 声明支持的 capability、参数、呈现、尺寸范围、素材授权与 renderer revision。模板本身不启动数据服务。clock renderer 接收统一 clock 阅读模型；agenda/timetable 等继续从原 capability 投影获得数据。

渲染路径：既有 CardFace/BoardCard 宿主 → 模板分支或原自由分支 → 共用外框、局部裁切、阴影、命中、坐标。定义纯 `templateLayout(cardBounds, reading, params)`，让 App、首页 preview、分享、Form 共用几何与字形度量，避免重演课程表高度和四角漏图问题。原生 ArkUI 实现 App/Form，不引入 Form WebView，也不把当前静态 HTML 外观缓存当动态模板运行时。

### 需要一起覆盖的调用点

| 现有文件 | 改动内容 |
| --- | --- |
| CardSchema.ets | 可选 design 校验与默认缺省；老卡走原分支 |
| CardViewSnapshot.ets | detached/storage/render snapshots 都保留 design；渲染签名包含 revision/params；不把运行投影存回 |
| CardFace.ets / BoardCard.ets / CardCanvas.ets | 模板外观分支，共享 clipping/hit/transform；模板物理边框避免叠两次 |
| DepthComposition.ets / SubjectDepthGeometry.ets | 复用前景投影和裁切变换；card ID、资源 owner 不变 |
| TemplatePackage.ets / TemplateIO.ets / TemplateFiles.ets | 资源收集、路径重写、导入 ID 重建、设计参数与许可打包 |
| LibraryStorage.ets / LibraryBackup | 现有事务/冲突草稿/恢复校验贯通可选字段；不加新作品数据库 |
| 画布复制、撤销、场景、自动轮换、云序列化 | 复核所有显式复制/白名单，防止某条路径漏 design 或 GC 掉个人照片 |
| WidgetRender / Form 投影 / 首页缓存签名 | 同一布局版本、资源就绪、局部像素更新；继续绑定 canvasId |

### 数据复用与性能

已有 CapabilityService 的 snapshots/pendingReads 会按 provider key 复用读取；保持这条路径。新模板不自建 timer、系统日历查询或电量监听。该缓存是进程内的，跨 App/Form 仍由原来的持久投影与刷新机制协调，不声称跨进程 Map 共享。

clock 同一次 render tick 派生时间和日期；timetable 同一来源可复用查询结果。外观改变不刷新数据；数据改变不重做照片处理。静态机身/纸张/裁切缓存 + 原生动态文本；只重绘发生变化的卡。

缓存键建议包含 renderer revision、实际像素尺寸、资源 hash、裁切和外观参数；动态文字 tick 不并入静态资源键。已落地的资源按 content hash 共享，同图多卡不复制原文件；保留一份可编辑原图、前景与必要尺寸派生文件。未写入的手势预览复用内存；落盘与异步缩图不阻塞退出。GC 扫正式作品、恢复版本、冲突草稿与待提交引用后才回收，不能只扫当前前台 canvas。

## 5. 老用户升级：无需批量迁移

**原 schema v2 的老 card 没有 design 时，渲染与存储维持原路径。** 初次升级不改 cardId/canvasId/groupId，不换尺寸、不重新绑定、不重排、不套模板。原来已经支持的 legacy 多 caps 迁移照旧，模板不夹带第二次迁移。

特别注意：当前 normalizeState 用 `raw.schemaVersion === 2` 判断 capability、其他版本走 caps。直接把文档版本改为 3 会走旧迁移路径，可能丢 capability。因此这次采用 v2 内可选扩展，同时补齐所有复制/归一化/导出路径。

- 创建或改成模板卡时，在同一 artwork 事务里提交 canonical card、设计配置、资源引用；准备好文件后再提交引用。失败保留旧 card 和草稿，不能写空画布占位。
- 正式上线前保留可恢复快照，按原并发冲突检查提交，不让数据刷新把旧 state 写回编辑结果。
- 模板 revision 固定；新设计版本另存，用户主动换外观时才更新，不按模板目录静默替换。
- 缺少 renderer/素材损坏时，用 canonical card 中的正常 capability、capBox、个人照片作为基础显示；不因模板分支出错删除整张卡。未知 design 原始数据保留，读取失败不进入删除/空库初始化路径。
- 当前 normalizeState 与 cardStorageShell 都是显式复制，旧二进制可能丢弃它不认识的 design。**从旧版向新版本升级**可通过缺省路径保证；**降级运行旧二进制后继续编辑新模板**需要另一份兼容导出，不能指望旧二进制保留新字段。
- 新模板包单独提升 package feature 标识/min reader；未知特性导入前拦截并保留原包。导出给旧版时生成基础外观副本，原件及个人照片留在新版本；不要把专属样式冒充成老 reader 可完整编辑的格式。
- 桌面始终解析原有 formId → canvasId。新增单卡铺满依然创建普通 canvas，从原来的系统 UI 选画布；不在 App 模板页另造绑定选择。

## 6. 分阶段交付与验收

### A. 首个可交付增量

照片景深时钟 + 翻页钟 + 纸本日期；卡片配置双入口；照片卡/无底；首页一键创建单卡 canvas、原编辑器添加模板 card。模板变体是 renderer，数据 capability 不变。老用户第一次启动无写入迁移。

### B. 紧接着做

作者设计的贴纸轮廓；几个真正适合组合的配方；用户自己的组合另存。跨卡景深沿用显式组合，不依赖模板主卡跨卡偷取日程数据。

### 必须通过的回归

- 真实历史 v1/v2、所有尺寸、空画布、场景、组、照片、课程表与损坏记录：加载后保存/重开，card 数量、capability、ID、几何、资源、桌面绑定逐项核对。
- 老作品打开不保存时 artwork 行不写入；改一张模板不能改其他 card 或全局主题；用户取消保持原样。
- 对每个入口验证：普通保存/撤销/重做/复制/分享/导入/恢复/场景切换/桌面冷启动；模板字段和照片引用不能漏。
- 资源落盘中断、事务失败、并发编辑、renderer 缺失、坏图片、缺前景、磁盘不足：保留上一版有效 card/画布，不能回空库。
- App/首页/Form 同时间同尺寸像素对照；180/300/420px 与不同屏幕比例；00:00/11:11/23:59、跨日、时区；透明轮廓命中、按压形状、阴影与裁切。
- 一张/多张/多画布复用同 provider：读取次数、重绘次数、首次打开/返回时延、峰值内存、派生文件数和总字节对比；采用工程当前基线记录 p50/p95，不能给未经设备测试的绝对帧率承诺。
