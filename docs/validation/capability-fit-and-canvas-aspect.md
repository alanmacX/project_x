# 完整信息显示与画布比例

画布的 `canvasAspect` 是文档属性，桌面的 `canvasWidth/canvasHeight` 是宿主属性。两者不得互相覆盖。桌面渲染把整张画布等比居中容纳到宿主内，卡片位置、尺寸、角度和内部内容使用同一个比例；留出的区域延续背景底色，透明模式保持透明。画框仍覆盖真实组件外沿。保存、切换、重新启动、自动轮换都从当前文档读取设计比例。

这解决的是系统横竖屏尺寸不同引起的布局变化。它不会尝试在不同长宽比中同时填满背景、放大每张卡片和完整保留原排版：这些目标不能同时成立。用户有意把卡片放出画布的裁切仍保留。

## 内容取舍

- 时间/日期/倒计时/纪念日/农历/世界时钟/进度/电量：按实际完整文字行、圆弧和辅助信息预算缩放。数字不使用强制最小字体造成宽度溢出。
- 台历：每周七列完整保留；详细月历仅在全部行及副信息有足够高度时展示，否则使用较简洁的完整月历/本周形态。
- 课程表：最小可读布局只要求一个完整课程项。空间增加后展示更多完整课程；不足时整项省略，以 `+N` 表示还有内容，不改变导入数据。下一课、每日概览共用课程项布局。
- 日程：根据行列预算取完整事件项，不使用内容容器裁切来掩盖溢出。
- 专辑：保留正方形封面和现有排版；两行标题和歌手信息按内侧可用高度适配，保留原先约定的文本省略号。
- 能力中的固定画布文字限制系统字体缩放，避免辅助字体放大突破既定内容区域；App 设置控件仍使用系统文字设置。
- 衬底的异形轮廓裁切只作用于材质，不能作为文字内容的兜底裁切。

## 验证

57 个生产模型/API 模拟回归套件通过，HarmonyOS debug HAP 编译通过。新增测试覆盖五种文档比例与五种宿主比例的等比适配、文档不被改写、完整课程行预算、专辑全文字行预算、时间字体边界，以及桌面原子包仅比例变化时的更新。

模拟器使用只读 `.fridge` 原生预览器检查全部能力，测试资源不写入用户画布，不随正式代码提交。该验证不等同于物理设备桌面横竖屏验收，也不能证明所有系统字体版本下的逐像素表现。
