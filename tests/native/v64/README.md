# v64：打开 App 时的顿感（2026-10-06）

本轮保留设计，重点从冷启动和后台返回两个入口定位停顿。使用 MatePad Mini / API 26 的 Release 模式构建、原有用户画布，HDC + hitrace（ace/graphic/app）以及 composer fps；没有把桌面组件刷新或模型测试当作启动帧率。

## 定位及修改

- 首屏一次性生成全部卡片，某次 UI VSync 任务耗时 400.75 ms：布局约 223 ms、绘制任务约 149 ms。启动后另有隐藏编辑页预建，增加无效工作。移除这项预建；首页缩略图不再重复绘制厚度、阴影和整套轮廓；图层使用原生 List。
- 未选中的卡片也生成四个完全透明的材质按钮及轮廓手柄。改成选择后生成，保留按钮出现和消失动画，消失动画结束再卸载。原生选择复查显示四个按钮，失焦后移除。
- 整卡构建改为每帧准备一张，完成后统一入场。零透明度和屏外位置会被渲染器剔除，无法预热；因此准备时使用 1% 透明度在目标位置生成纹理，再提交屏外起点，下一帧开始原有入场动画。卡片持续使用同一组稳定 ID，不显示逐张入场或逐张弹出能力。
- 临界过渡原先依赖 FrameCallback.onIdle。SDK 明确说明空闲不足 1 ms 时可以推迟回调，忙碌首屏不能依赖它保证推进。改为 onFrame 后排队推进，编辑截图另有 300 ms 上限和迟到纹理释放；首次进入不再因截图等待而挂住。scene-idle 仍保留为独立空闲标记。
- 返回前台的 PageShow、Foreground 连续改变 tick、刷新整页。合并一次，在系统窗口入场后 350 ms 更新；同一分钟的时间值保持稳定，无定时规则时不反复赋值空数组。手势或 App 过渡正在进行时继续延期，离开页面取消。
- 启动维护及智能取色避开入场和手势；轮廓缓存只在素材/主轮廓/准备轮廓变化时重新编码，位置变化不再重复编码完整轮廓。
- 能力拖动/缩放更新局部观察对象，避免逐帧刷新整个设置页。该项属于上一条整体性能请求的补充，当前启动结论不依赖它。

## 结果及口径

| 场景 | 观测 |
| --- | --- |
| 分帧准备前的冷启动 | 单个 UI VSync 400.75 ms；入场合成帧最长间隔 116.71 ms |
| 相同横屏画布，两轮未中断启动 | 最长 UI 准备帧 87.41 / 91.76 ms；入场约 108 / 120 fps，最长帧间隔 16.76 / 8.53 ms |
| 第三轮 | 入场采样约 118 fps、最长 16.69 ms，但结束标记提前至 +848 ms，属于被打断的过渡，不能作为完整启动耗时验收 |
| 后续竖屏深色、用户修改后的画布 | 最长 UI 准备帧 94.06 ms；纹理准备 +754 ms、入场 +777 ms、结束 +1323 ms；入场约 110 fps、最长 16.8 ms |
| 同一竖屏场景后台返回前/后 | UI 帧 48.83、28.58 ms → 最大 10.34 ms；刷新移出系统窗口入场并去重 |

scene-ready 只代表数据可用，scene-idle 是首个有空闲预算的帧标记，均不等同“所有卡片已呈现”。新增 surfaces-ready、arrival-start、arrival-end 明确区分准备和呈现。没有声称准备阶段已达到 120 fps：仍有约 90 ms 的单卡构建帧；入场动画 520 ms 也包含在整体打开时间中。本轮消除了所采样入场中约 117 ms 的中途断帧，但不能据此保证所有设备、所有画布都满刷新率。

竖屏样本的卡片内容、系统主题和时间已变化，因此只作为追加覆盖，不与横屏启动总耗时直接相减。worker 线程的长任务不算 UI 线程长帧；JSON 中 slow_tasks 包含进程的其他线程，需结合 trace 的线程 ID 解释。

## 验证及复现

- 全部 23 个 tests/*.cjs 通过；新增回归覆盖没有 idle 预算时推进、按帧准备、过渡起点先提交、销毁取消、前台重复回调合并、手势期间延期、后台取消、同分钟时间去重。
- 轮廓缓存回归验证移动/旋转连续保存不重复编码，新素材版本和删卡正确失效。
- Release assembleApp 成功，签名包覆盖安装；git diff --check 通过。用户画布及素材未由测试删除或重建。
- 编辑进出额外采样 117–120 fps；首次编辑仍有约 304 ms 的准备等待，后续约 24 ms。本轮用户澄清重点是打开 App，这组结果不代替启动验收。
- 未重新进行全部手机/折叠真机、全部能力、长时间压力/内存、桌面组件重启恢复验收，上一轮多设备报告仍为独立覆盖。

`HDC_TARGET=<设备 ID> python3 tests/native/v64/launch_bench.py` 冷启动；设置 `FRIDGE_RESUME=1` 测 Home 后返回。脚本将临时 trace/log/fps 写到 /tmp/v64-launch.*，不提交可能包含用户内容的原始 trace。运行 `python3 tests/native/v64/launch_stats.py` 输出摘要；采样期间保持同一方向、画布和系统设置，且不要切换其他 App。composer fps 是屏幕合成帧观测，不是逐组件 FPS。
