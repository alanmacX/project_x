`ProbeAbility.ets` 是当时使用的诊断 Ability 源码，放入一次性测试工程并复制当前生产 model 模块即可构建，不能放进产品入口。`events.txt` 是真机日志中的测试事件摘录，不含账号或用户画布。模式通过 `aa start ... --ps mode <mode>` 选择，每个模式前重启测试进程。不要在任何有用户数据的安装上运行这些模式。

## 原生执行结果

- `legacySeed`：先用系统 Preferences API 写入旧 XML 格式的目录和画布，包含位置、宽高、旋转和倒计日配置。
- 保留数据覆盖安装测试包（1002007 → 1002008）；`verifyUpgrade` 使用当前生产 LibraryStorage，确认目录及画布原始 JSON 逐字不变。这是代表性旧格式迁移，不冒充所有线上旧包或完整 OS OTA 的验收。
- 两个独立 LibraryPreferences session：先提交新画布，再提交先前读取的旧画布，后者被拒绝；冲突改动存在原生 SQLite 的草稿表。
- 提交引用不存在文档的目录被拒绝，原目录保留。
- 原生文件备份使用真实 TextEncoder、SHA-256、fsync、rename，原生读回校验通过。
- `crashBefore`：使用同一原生 RDB 事务 API 的专用双行临时表，修改第一行后在未提交状态强制停止测试进程；重启读取两行都为 old。
- `crashAfter`：两行修改并提交后强制停止；重启读取两行都为 new。不是实际拔电测试；生产适配层本身的四进程/SIGKILL 测试见自动化套件。
- 三轮成功画布写入后形成三个备份代。仅截断测试沙箱的最新代 3，原生读取器跳过损坏文件，读到完整代 2；SQL 当前数据没有被测试回退覆盖。
- 复制原生数据库后 `integrity_check=ok`，提交计数 3，冲突草稿 3，所有内容均为合成数据。
