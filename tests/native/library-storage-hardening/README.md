# 画布丢失：原因边界与防复发验收

## 已有证据

- 真机原 `fridge_store` 只剩默认目录和空画布；10 月 25 日已有零字节 `.broken` 标记。原素材仍在，3 个有效桌面绑定在独立 SQLite 中。
- 10 月 27 日原代码日志有 NativePreferences `closed:Get/Put/FlushSync`。旧代码在 App、Form、绑定与同步入口反复调用 `removePreferencesFromCache`，编辑器继续持有被移除的实例。SDK 明确要求停止使用被移除的实例。
- 旧读取接口把“不存在”表示为默认空字符串，`readCatalog('')` 返回新默认目录，空输入 hydration 可返回默认画布。调用层缺少“确为首次安装”的证据，缺少初始化失败后的独立保存禁令。这构成把读取失败误当成新库的应用层缺陷。
- 旧 XML 整体写入由多个进程发起；SDK 的跨进程一致性要求没有在旧实现中落实。不能用“每个画布不同 key”推断整份 XML 可以安全并发更新。
- 无完整的 10 月 25 日操作轨迹，不能断言 OS 更新、某次清缓存调用或某一轮并发写就是最初触发点。`.broken` 标记与当前 closed 日志不能串成已经证实的同一次因果事件。
- 本次覆盖安装后桌面缓存画面消失，是调试操作造成的额外损失；绑定 ID 未变不能作为缓存画面已保全的证据。

## 本轮新增保护

1. 已有事务存储之上增加读取版本检查：提交前比较原始行值，旧快照不得覆盖新编辑；被拒绝的新改动会单独保存为冲突草稿，每个范围保留三份，相同重试去重，并明确提示保存未完成。Form 的能力结果与日历操作复用读取源记录的 session。
2. 提交前校验画布结构；目录变更和删除会在同一事务内校验所有引用。初始化过的库缺目录、迁移源缺记录、损坏标记均拒绝初始化。编辑器初始化未成功时独立拒绝 save。
3. 保留上一行并增加数据库外备份：仅存画布/目录/共享课表 JSON，不复制原图或派生轮廓；SHA-256 校验、临时文件 fsync 后原子改名，保留三代。连续编辑合并，空闲约 1 秒执行，持续编辑时约 5 秒捕获一次；后台回执不触发备份。备份取自独立一致事务，失败不改变已提交库，不覆盖上一份备份，清理本次失败临时文件。
4. 备份读取器会跳过损坏或截断的最新代，选择较早的完整代；没有有效代则报错，不生成空库。尚未把物理损坏的数据库自动替换成备份；保留副本供显式恢复，不宣称所有磁盘故障都可自动恢复。

## 验证

- 103 套回归测试；存储套件验证失效读取防线、版本冲突、目录与文档一致性、回滚/重试、初始化保存禁令。
- 四个真实独立 Node 进程同时执行生产适配层 SQL，160 次独立键提交无互相擦除。
- 对执行生产事务的子进程在第一次写入后 SIGKILL：重启读取完整旧画布和旧目录；提交后 SIGKILL：重启读取完整新画布和新目录。
- 独立文件测试覆盖备份轮转上限、SHA-256、截断最新代、未完成临时文件、磁盘满异常、错误目录引用和全部备份失效。
- 原生编译、生产页面打包检查另行记录。独立真机 probe 编译到打包步骤，但现有签名仅授权原 bundleName，无法签署独立测试包，未安装；未以再次覆盖安装原 App 来绕过该限制。本轮不宣称已完成新事务/备份的真机运行验收或真实断电试验。

## 发布边界

不能以测试数量保证绝不丢失。需要补齐独立签名测试包的真机验收，以及从实际线上旧包升级到新库的完整验收，再批准全量发布。当前真机的原画布仍未恢复，保护代码不会找回已经缺失的内容。不得删除原 XML、素材或现有备份来让新库看起来正常。

追加验收：用户确认卸载旧应用后，在全新、明确标记为测试专用的沙箱中完成了原生事务、旧 XML 格式覆盖升级、强制停止前后重启和备份损坏回退验收。详见 `../library-storage-device/README.md`；上文签名阻塞为当时状态，不代表后续验收仍未完成。
