# 自选 URL、RSS 与内容源

2026-10-31，接入方案调查；当前 App 尚未新增网络内容能力。目标：数据直接从用户选择的源来到设备，不建立自己的服务端，创作与离线预览继续在本地。

## 建议范围

| 顺序 | 内容 | 用户操作 | 展示 |
| --- | --- | --- | --- |
| 1 | 公开 HTTPS RSS 2.0 / Atom 1.0 | 粘贴源地址，确认内容预览 | 最新标题、2–4 条列表、可选封面 |
| 2 | HTTPS JSON | 粘贴 URL，从返回字段中点选标题/数值/单位/链接 | 单值、简短状态、列表 |
| 后续 | 登录型/私有订阅 | 需要本机凭据配置与额外授权流程 | 沿用同一数据模型 |

普通网页 URL 首先探测 HTML 中声明的 RSS/Atom 地址，找到后让用户确认；没有源就显示无法识别和“输入源地址”。不要通过任意脚本、远程 HTML 渲染或自动登录来扩大首版范围。纯网页抓取受站点结构和访问策略影响，独立评估。

入口可放在“添加卡片 → 订阅”，一个 sheet 完成 URL、预览、展示方式；已有订阅直接可选。卡片设置中更换源。不要让普通用户输入 CSS selector、JS 或复杂 JSONPath；JSON 先给字段树，进阶映射后续再做。

## 协议与平台核对

- [RSS 2.0 规范](https://www.rssboard.org/rss-specification)：channel/item 提供标题、链接、摘要等；ttl 是更新提示，源内容与表现形式可独立处理。
- [Atom RFC 4287](https://www.rfc-editor.org/info/rfc4287/)：另一种标准 XML feed，需要正确处理命名空间、稳定 ID、链接关系与日期。
- [HTTP RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-conditional-requests)：ETag/If-None-Match、Last-Modified/If-Modified-Since 可用于条件请求，304 保留原数据。
- 本机 Harmony SDK 已确认 `@ohos.net.http.d.ts` 有 HttpRequest/requestInStream，`@ohos.xml.d.ts:611` 有 XmlPullParser。正式实现需在当前目标 API 的原生探针中验证流式大小限制、重定向控制、XML 实体和编码处理。

## 同源共享与离线策略

`sourceId → 原始响应缓存 → 规范化内容/revision → 多卡片投影 → 多个桌面实例`。

1. Source 与画布分开保存。配置记录 URL、适配器版本和本地 source ID；显示主题不参与请求 key。仅做安全的 URL 规范化：不擅自删除 query 或改变其顺序，避免破坏签名地址。
2. 同 source 同时请求合并；带认证的源还需按凭据身份区分。一个画布或桌面实例刷新不能再拉一遍同一数据。只有规范化内容发生变化才增加 revision、重绘对应卡片。
3. 前台打开、用户刷新、系统允许的后台生命周期统一经过调度器。按源缓存策略、退避和用户选择控制频率；前台显示只读缓存，网络不阻塞页面。桌面刷新受系统调度，具体机制通过 Form 原生探针确认。
4. 超时/断网/坏 XML/空响应保留最后有效内容。明确有效空 feed 和解析失败；前者可以显示空态，后者不能抹掉缓存。错误不写空创作库、不删除 canvas、不改 binding。
5. 建议初始预算：单响应解压后 1MiB、最多 50 条、正文文本最多 4000 字/条、下载总时限 15 秒、重定向最多 3 次。封面按展示尺寸采样，单图与总缓存分别设预算；缓存优先回收，原始用户素材不进入该回收器。数值在原生探针后调整。

## 输入与隐私

首版限定公开 HTTPS 地址，拒绝 file/content/data/javascript 等 scheme、环回/私网/链路本地目标；每次重定向重新校验，不将认证头带到其他 origin。读取 XML 时禁用外部实体/DTD/外部资源展开；不执行摘要中的脚本、样式、事件和 HTML，只保留正文文本及经过校验的链接。处理压缩后体积上限、嵌套深度、坏编码、重复 ID、相对链接与缺失日期。

含 token 的订阅地址视为私有内容，不写诊断日志。公开分享只传外观与源类型；即便是看似公开 URL 也由用户选择是否带出，默认不传。凭据留在本机安全存储，私人整库备份需独立策略。删除卡片不级联删共享 source；删除 source 先查引用，再给关联卡片保留样式与未配置状态。

## 与模板结合

模板的标题位、列表位、封面位读取同一 source 的不同投影。仪表风格适合单值/简短状态，纸本适合阅读摘录，色块可做标题与大封面。展示方式需要独立的长度和空态适配，不能把 RSS 原始 HTML 塞进所有卡片。

新增订阅 provider 要一起更新 CardSchema、共享清洗、数据调度、App/Form 展示、浏览器适配器、设计契约和导入版本兼容；旧的 weather/fetch 已退役实现不直接解封。本次设计样稿仍只使用现有能力。

## 开工验收清单

RSS/Atom 本地固定样本、CDATA、命名空间、中文编码、HTML 清洗、错误内容、超大/压缩响应、重定向、304、429/Retry-After、离线、旧回调迟到、共享源请求去重；App/两个 Form 同源一致；缓存被清理后作品和绑定完整；源数据不进入公开导出。完成稳定性发布阻断项后安排。
